# 08 — UI Specification

## Visual identity: "flight recorder"

Real aircraft flight recorders are painted bright orange so they can be found in wreckage. That's our brand and a line in the pitch.

- Background `#0B0B0C`, surfaces `#141416`, borders `#26262A`, text `#E8E8EA`, muted `#8A8A92`
- Accent (brand, primary buttons, culprit highlight): safety orange `#FF6B00`
- Pass `#22C55E`, fail `#EF4444`, reused/ghost `#3F3F46`, changed `#F59E0B`
- Fonts: Inter (UI), JetBrains Mono (keys, JSON, numbers)
- Blame heat on nodes: interpolate `#3F3F46` → `#F59E0B` → `#FF6B00` → `#EF4444` by normalized score
- Dense, technical, calm. No gradients, no emoji, no stock illustrations.

## Runs

Table: outcome badge · origin · question (truncated) · n_steps · predicted culprit (step_key chip + score bar) · created. Filters: outcome, origin, split, fault type, search. Row click → Run Detail. Paginate server-side.

## Run Detail (hero)

Layout: header strip, then three columns (left 20% meta · center 55% graph · right 25% inspector), timeline strip under the graph.

- **Header:** question; gold answer vs. final answer; outcome badge; F1; origin; parent run link if a replay; buttons **Diagnose**, **Auto-repair**, **Compare with parent**.
- **Graph (React Flow + dagre, left→right):** nodes = steps, edges = deps. Node shows step_key (mono), name icon, and a short output_text. Fill color = blame heat after diagnosis. Rank-1 node: orange outline + pulsing ring + "#1" badge. Replay runs: reused nodes rendered ghosted with a dashed border and a "reused" tag; executed nodes solid. Click a node → inspector.
- **Timeline strip:** steps in execution order as bars; bar height = blame score; hover shows key.
- **Inspector tabs:**
  - *Why* (default for ranked steps): score, rank, the 3 reasons with evidence snippets in quote blocks.
  - *I/O:* input and output JSON, collapsible, mono.
  - *State:* state_snapshot.
  - *Replay:* JSON editor (textarea + validation) prefilled with the step's output, "Show blast radius" (highlights affected nodes on the graph), **Replay from here** button.
- **Ground-truth toggle** (small, off by default): shows the label/fault marker so judges can see the model was right. Off by default so the diagnosis is seen first.

## Replay result

Toast/card after a replay: outcome change (fail → pass), "Re-executed 4 · Reused 13 · Saved 6,210 tokens", buttons **Open run**, **Compare**.

## Auto-repair panel

Drawer listing attempts as they finish: step_key · strategy · outcome · executed/reused. The winning attempt is highlighted with a **Compare** button.

## Compare

Banner: outcome A → B, first divergence key. Two-column table aligned by step_key with status chips (same / changed / only A / only B). Changed rows expand to an inline word diff of output_text (green/red). Above the table, a mini graph of run B with changed nodes highlighted.

## Evaluation

- KPI cards: Top-1 (seen), Top-1 (held-out), Top-1 (organic), avg % reused, auto-repair @top-3.
- Bar chart: model vs. 4 baselines on Top-1/Top-3 per test set.
- LOFO table: fault type × Top-1/Top-3/MRR.
- Per-fault-type bars.
- Replay savings: bisect replays vs. linear scan; reused % histogram.
- Small "how we evaluated" note: split by task, held-out types, organic labels by counterfactual resampling.

## Fleet insights

"Where do our agents fail?" Bar charts by culprit step name and by top reason; clicking a bar opens Runs filtered to it. Headline sentence generated from data, e.g. "41% of failures originate in retrieval."

## Live Lab (demo driver)

Pick a test task (search), optionally choose a fault type + target step (dropdown populated with applicable keys), **Run**. Shows the run streaming into the graph (poll), then auto-runs diagnosis, then offers **Auto-repair**. This screen is how the 90-second demo is driven.
